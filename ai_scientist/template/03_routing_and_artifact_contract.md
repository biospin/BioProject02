# 03 — 라우팅 + 산출물 계약 (원칙)

에이전트가 여럿이면 두 가지를 정해야 한다: **어떤 요청을 누구에게** 보내나(라우팅), **무엇을 주고받나**(계약).

## (A) 자연어 라우팅 — 이름을 몰라도 배정된다

요청에 에이전트 이름이 없어도 배정되도록 표를 만든다.

| 요청 (자연어 예시) | 첫 에이전트 |
|---|---|
| "분석 돌려줘 / 재실행 / eval·통계 / 오류 분석" | `{{DOMAIN_AGENT}}` |
| "초안·섹션 써줘" | 원고 작성 |
| "그림 만들어줘 / 번호 정리" | 원고 작성 (그림 스크립트 실행) |
| "선행연구 / 관련연구 / 스쿱 확인" | 문헌 조사 |
| "차별화 각도 / 뭘 새로 해야 하나" | 차별화 전략 |
| "가설·설계·분석계획 점검" | 방법론 감사 |
| "제출 전 적대적 검토 / 그림 QA" | 내부 적대검수 |
| "인용 검증 / 이 논문 진짜 있나" | 내부 적대검수 — **반드시 검증 스크립트를 실행한다. 눈으로 보지 않는다** |
| "정식 venue 리뷰 시뮬레이션" | 외부 리뷰 — **게이트 ① 통과 후에만** |
| "발표자료" | 발표 |
| "어떤 순서로 엮을지 계획만" | 계획 (실행 안 함) |
| **여러 단계를 엮는 요청** ("풀 파이프라인 / 제출 준비 / 그림만 다시 / 지적 반영") | **오케스트레이터 Skill** |

**핵심:** 단일 단계는 **직행**, 여러 단계를 엮는 요청은 **오케스트레이터로 모여** 정해진 순서로 실행되고 **부분 재실행**을 처리한다.

## (B) 산출물 계약 — 단계 간에 무엇을 넘기나

각 단계는 **다음 단계가 읽을 파일**을 남긴다. 대화가 아니라 **파일이 상태**다.

| 단계 | Writer | 산출물 | 다음이 읽음 |
|---|---|---|---|
| 분석·eval | `{{DOMAIN_AGENT}}` | 결과 파일 + 통합 요약 | 집필·검수 |
| 집필+그림 | 원고 작성 | 원고, 그림 디렉토리 | 검수·리뷰·발표 |
| 검수 | 내부 적대검수 | 적대 노트 + 그림 QA | 집필(수정) |
| 🔒 **검증 게이트 ①** | (커밋 전) | `{{VERIFY_GATE_1_CMD}}` 결과 | 사람 |
| 정식 리뷰 | 외부 리뷰 | 리뷰 노트 | 집필(수정) |
| 🔒 **검증 게이트 ②** | (공개 전) | `{{VERIFY_GATE_2_CMD}}` 결과 | 사람 |
| 발표 | 발표 | 슬라이드·발제 | 사람 |
| 상태 핸드오프 | (전원) | `{{HANDOFF_FILES}}` | 다음 세션 |

이 계약 덕분에 **부분 재실행**이 가능하다 — "그림만 다시"는 그림 스크립트만, "지적 반영"은 하류 집필만 돈다.

> ⚠️ **"리뷰 → 집필(수정)" 화살표에는 계약을 따로 건다.** 이 수정은 게이트 ① **이후**에 일어나므로, 무엇을 바꿔도 되고 무엇은 안 되는지(특히 **검증된 숫자**)를 명시하지 않으면 계약이 비어 있는 구간이 된다. 가능하면 **도구 권한으로** 좁힌다([02](02_agents_and_roster.md)).

## 스키마로 굳힐 것

자연어가 아니라 **기계가 검사할 수 있는 형태**로 고정한다.

| 대상 | 필수 |
|---|---|
| 주장 출력 | `claim_level`(기본값 `{{CLAIM_LEVEL}}`) + 검수 상태 |
| 검수 리포트 | 항목별 판정 + 종합 판정 (어휘는 [04](04_automated_review_and_governance.md) 참조) |
| 실험 결과 | `{{METRIC_FIELDS}}` + 실행 시점 커밋 해시 |

### ⚠️ 스키마는 "선언"이 아니라 "검증"이어야 한다

가장 흔한 함정: 산출 스크립트가 docstring에 *"○○ 스키마 형식으로 출력한다"* 라고 **적어만 두고 검증은 하지 않는 것.**
그러면 위반은 **아무 신호도 내지 않고** 몇 주씩 쌓인다 — 형식이 *주장*일 뿐 *검사*가 아니기 때문이다.

**규칙 셋:**
1. **산출 시점에 검증한다.** 검증에 실패하면 파일을 쓰지 않는다.
2. **현장에서 필요해 붙은 필드는 삭제가 아니라 스키마 확장으로 흡수한다.** 규율을 지키려고 유용한 정보를 버리지 않는다(예: 값이 *실측인지 fallback인지* 구분하는 표시).
3. **스키마 자체의 참조 해석을 회귀로 고정한다** — 참조는 지연 해석돼서 **빈 입력에선 통과하고 실제 데이터에서만 터진다.**

> ⚠️ **CI에 blocking으로 거는 시점을 주의한다.**
> 기존 산출물에 위반이 남아 있는 상태로 켜면 **"원래 빨간 CI"** 가 되고, 그러면 아무도 CI를 보지 않는다.
> **먼저 위반을 해소하고, 그다음에 켠다. 순서를 지키는 것도 설계다** — 게이트를 켜는 시점이 잘못되면 게이트 자체가 무력해진다.

## "지어내지 않기"를 계약에 박는다

계약은 *무엇을 넘길지*뿐 아니라 **없는 것을 있는 척 넘기지 않기**까지 규정한다.

- **`<FILL>` 표기** — 아직 없는 것을 **없다고 표시**하는 장치. 비워두는 것과 다르다.
- **근거는 봉인 문서·실물 코드·실물 기록뿐.** 인용할 땐 **`파일:줄` 또는 기록 id**를 밝힌다.
- 파생 규칙 3개:
  - ❌ **발표자료·슬라이드·메모의 숫자를 합격 기준으로 쓰지 않는다** — 발표자료엔 *관측값*이 실리지 *기준값*이 안 실린다
  - ❌ **계획을 자산으로 쓰지 않는다** — "앞으로 할 일"이 몇 줄 아래서 "이미 있는 것"으로 승격되는 일이 실제로 일어난다. 있다고 적혀 있으면 **열어서 확인한다**
  - ❌ **도구가 "못 찾겠다"고 한 것을 통과로 처리하지 않는다** — 조회 실패 시 약한 대체 검색으로 내려가 `OK`를 주는 도구가 있다. 실패는 **에스컬레이션**한다
