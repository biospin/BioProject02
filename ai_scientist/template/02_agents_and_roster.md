# 02 — 에이전트 명부 · 권한 · 격리 (원칙)

## 원칙

"한 명의 만능 에이전트"가 아니라 **벤치(bench)별로 역할이 나뉜 랩**으로 만든다. 각 에이전트는 시스템 프롬프트·**도구 권한**·산출물 계약을 파일로 갖는다.

## 로스터 — 재사용 9 + 도메인 슬롯 1

| 벤치 | 에이전트 | 역할 | 권장 권한 |
|---|---|---|---|
| **분석실** | `{{DOMAIN_AGENT}}` | **(도메인 슬롯)** 파이프라인 대표 · eval · 통계 · 결과 파일 유지 | 읽기·쓰기·실행 |
| 문헌·기획 | 문헌 조사 | 선행연구·관련연구·스쿱 확인·인용 목록 | 웹·읽기·쓰기 |
| 문헌·기획 | 차별화 전략 | 차별화 각도 + **가장 싼 입증 실험** | 웹·읽기·쓰기 |
| 문헌·기획 | 방법론 감사 | 가설·기여문·기준선/절제 설계, 누수·통계 감사 | 읽기·쓰기·실행·웹 |

## 설계상 중요한 세 구분

### (1) 계획하는 에이전트 ≠ 실행하는 입구

- **계획 에이전트** — 여러 단계를 어떤 순서로 엮을지 **계획만** 한다. 서브에이전트는 서브에이전트를 낳지 못하므로 실행할 수 없다.
- **실행 입구(Skill)** — **메인 루프**가 직접 실행한다. "풀 파이프라인", "그림만 다시", "지적 반영" 같은 요청이 여기로 들어온다.

둘을 한 파일로 합치면 "계획은 했는데 아무도 실행하지 않는" 상태가 된다.

### (2) 도메인 특수성은 슬롯 하나에 격리

로스터에서 도메인 고유는 `{{DOMAIN_AGENT}}` 하나뿐이고 나머지는 전부 연결조직이다. 도메인 지식이 집필·검수 에이전트로 새어 나가면 **레이어 B의 재사용성이 사라진다.**

### (3) 내부 검수 ≠ 외부 리뷰 — 격리한다

| | 내부 적대검수 | 외부 리뷰 |
|---|---|---|
| 언제 | 자동 리뷰 루프 안 | **게이트 ① 통과 후** |
| 입력 | 원고 + 결과 파일 + 내부 노트 | **원고 패키지만** — 분석 과정·내부 논의·검수 노트 **차단** |
| 역할 | 고치라고 잡아내는 자기검수 | 심사자 눈으로 보는 시뮬레이션 |

**격리 이유:** 리뷰어가 내부 맥락을 알면 **실제 심사자가 겪을 정보 부족을 재현하지 못한다.**
리뷰 상단에 **사용 모델·입력 범위**를 기록하고, 같은 모델 계열이면 *"simulated review (외부 심사 아님)"* 임을 명시한다. 진짜 다양성이 필요하면 **다른 모델 계열**로 실행한다.

## ⚠️ 처음부터 정할 것 — 권한을 "말"이 아니라 "도구"로 강제

규율을 프롬프트로 부탁하면 지켜지지 않는 순간이 온다. 특히 **"조금만 고쳐"** 는 통째로 다시 쓰기로 이어지고, 그 과정에서 **검증이 끝난 숫자·인용이 조용히 바뀐다.**

**규칙 3개:**

1. **모든 에이전트에 도구 목록을 명시 선언한다.** 미선언은 대개 *전체 상속*이다 — 격리하겠다고 써놓고 도구는 다 주는 상태가 가장 흔한 실패다.
2. **검수 계열에서 쓰기 권한을 뺀다.** 검수자가 원고를 고칠 수 있으면 검수와 집필의 경계가 사라진다.
3. **게이트 이후 수정은 "편집만"으로 좁힌다.** 새 파일 생성이 필요하면 오케스트레이터가 **빈 스텁을 먼저 만들고** 수정 에이전트가 채우게 한다. 수정 단위(hunk) 크기 상한도 함께 건다.

> 권한을 뺄 때는 **부작용까지 설계한다.** 쓰기를 막으면 로그 파일도 못 만든다 — 그래서 스텁 선생성이 필요하다. 작은 수정으로 담기지 않는 지적은 **"구조적 이슈"로 에스컬레이션**한다.

**자기 점검:** 로스터를 한 줄로 훑으며 *"이 에이전트가 하지 말아야 할 일을, 도구가 막고 있는가 말이 막고 있는가"* 를 표시한다. 말이 막고 있는 칸이 **의도된 것인지** 확인한다.

## 에이전트 발행 규칙 (구현 디테일)

서브에이전트가 무력해 보이는 건 대개 권한이 아니라 **프롬프트 문제**다.

- 첫 줄에 **무엇으로 실행할지** 명시한다(슬래시 커맨드·스킬 대신 직접 실행 등)
- 실행할 코드를 **copy-paste 가능한 형태로 직접** 포함한다 — 추상 지시 금지
- **인터프리터·환경 경로를 명시**한다 (`{{ENV}}`)
- 에러 발생 시 수정 후 재시도하도록 명시한다
- 엉뚱한 자동화를 유발하는 표현("설정 스캔해서 업데이트" 등)을 피하고 **구체적 명령**으로 대체한다

**검수 에이전트 발행 전 필수 확인** — 하나라도 미충족이면 발행하지 않는다:
1. 리뷰 대상의 upstream 의존성이 **모두 완료**됐는가
2. 더미·스모크 테스트가 아닌 **실제 데이터** 결과인가
3. 결과 파일이 실제로 존재하고 **수치가 채워져** 있는가
