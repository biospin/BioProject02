# INTEGRATIONS — Git · 이슈 트래커 · 위키 · 알림 연동 가이드

하네스가 실제로 굴러가려면 **네 시스템**이 하나의 루프로 닫혀야 한다: 코드(Git) · 작업(트래커) · 지식(위키) · 신호(알림).

이 문서는 **JIRA / Confluence / Telegram**을 기준으로 쓰되, 각 절 첫머리에 **원칙**을 두어 다른 도구로 바꿔도 배선이 유지되게 했다.

---

## 0. 원칙 — 무엇을 어디에 두나 (가장 먼저 정할 것)

⚠️ **네 시스템에 같은 내용을 중복 저장하면 반드시 어긋난다.** 시스템마다 **단일 정본(single source of truth)** 을 정한다.

| 정보 | 정본 | 나머지 시스템에는 |
|---|---|---|
| 코드·설정·스키마 | **Git** | 링크만 |
| 실험 결과·산출물 | **Git**(`{{EXPERIMENT_DIR}}`) | 수치는 인용 시 `파일:줄` 명시 |
| 작업 상태·결정·승인 | **트래커 코멘트** | 위키엔 요약 + 티켓 링크 |
| 합의된 규약·가이드 | **위키** 또는 리포 문서 (**한 곳만**) | 다른 쪽은 포인터 |
| 진행 신호·알림 | **채팅** | **정본 아님** — 채팅 내용을 근거로 쓰지 않는다 |
| 개인 작업 로그 | 로컬(`{{HANDOFF_FILES}}`) + 백업 | 공유 기록은 트래커·PR |

> **핵심 규율:** 채팅 메시지와 개인 로그는 **상태의 근거가 아니다.** 상태를 인용할 땐 **커밋 해시 · `파일:줄` · 코멘트 id** 중 하나를 밝힌다.

**루프 배선:**

```
트래커 이슈 할당
   └→ 알림 봇 감지 → 채팅으로 알림          (봇은 코드를 쓰지 않는다)
        └→ 담당자가 CLI 도구로 실제 작업
             └→ 커밋(이슈 번호 포함) → PR
                  └→ 스마트 커밋으로 트래커 상태 자동 갱신
                       └→ 완료 시 위키에 정리 (결정·근거)
```

## 1. Git

### 원칙
- **대화가 아니라 파일이 상태다.** 재개 가능성은 커밋과 산출물에서 나온다.
- 실험은 **커밋 해시와 함께** 기록한다 — 없으면 재현이 불가능하다.

### 브랜치·커밋 규약

```
<type>/<{{TRACKER_KEY}}-번호>-<사용자>-<짧은설명>
```

| prefix | 용도 |
|---|---|
| `feat/` | 새 기능 (코드·스크립트) |
| `docs/` | 문서·스키마·체크리스트 |
| `fix/` | 버그 수정 |
| `infra/` | 설치·컨테이너·자동화 |

> ⚠️ **브랜치를 만들기 전에 티켓을 먼저 만든다.** 티켓 없이 시작하면 번호를 못 넣고, 나중에 붙이려면 브랜치를 새로 파야 한다.

### 저장소에 두지 않는 것

- ❌ **자격증명·API 토큰** (아래 §5)
- ❌ 대용량 원본 데이터 — 정본은 외부 스토리지, 리포엔 **매니페스트·인덱스·결과만**
- ❌ 벤더링한 대용량 라이브러리 — 필요하면 폴백 경로를 두고 커밋은 팀 판단
- ⚠️ 개인 작업 로그는 추적 대상에서 제외하되 **백업 경로를 정한다**(로컬 디스크는 유실된다)

### PR

- 본문에 **티켓 링크 + 무엇을 검증했는지**를 적는다
- **검증 게이트 ①을 통과한 뒤** 병합한다 → [01](01_two_layer_architecture.md)
- CI 결정론 검증기를 **blocking**으로 건다 → [04](04_automated_review_and_governance.md)

## 2. 이슈 트래커 (JIRA 기준)

### 원칙
- **티켓의 실제 상태는 본문이 아니라 최신 코멘트에 있다.** 승인·결정·지적은 코멘트로 쌓인다.
- 상태를 바꾸는 행위(승인·서명·판정)는 **반드시 코멘트로 남긴다** — 채팅에만 남기지 않는다.

### ⚠️ 조회 시 반드시 코멘트를 포함한다

**대부분의 트래커 API는 기본 응답에서 코멘트를 뺀다.** 이걸 모르고 조회하면 *"승인 대기 중"* 이라고 적었는데 승인이 며칠 전에 이미 있는 사고가 난다([APPENDIX 사례 3](APPENDIX_CASE_BIOP02.md)).

```bash
# ✅ 개별 티켓 — comment 포함
curl -sS -u "$TRACKER_EMAIL:$TRACKER_TOKEN" \
  "https://{{TRACKER_HOST}}/rest/api/3/issue/{{TRACKER_KEY}}-123?fields=summary,status,assignee,description,comment"
```

- **목록(JQL) 조회 결과에는 코멘트가 없다.** 응답이 과대해지므로 목록엔 싣지 않는다 →
  **실제로 손댈 티켓은 개별로 한 번 더** 조회한다.
- MCP·SDK를 쓸 때도 `fields`에 `comment`를 **명시**한다.

### 스마트 커밋 (커밋 → 티켓 자동 갱신)

```bash
git commit -m "{{TRACKER_KEY}}-27 #in-progress 타일링 스크립트 초안"
git commit -m "{{TRACKER_KEY}}-27 #done 파라미터 확정 + 회귀 테스트 추가"
git commit -m "{{TRACKER_KEY}}-27 #comment 1건 파일럿: 8.3분, 4821 patches"
```

전제: 트래커와 Git 호스트가 연결돼 있어야 하고, **커밋 작성자 이메일이 트래커 계정과 같아야** 한다(다르면 조용히 무시된다).

### 티켓 본문 서식 (권장)

```
■ 목적 / 배경        왜 필요한가
■ 할 일              체크 가능한 단위로
■ 산출물             파일 경로까지
■ 완료 조건          Acceptance Criteria (체크박스)
■ 잔여·후속          정직 보고 — 못 한 것과 그 이유
■ 근거               파일:줄 또는 코멘트 id
```

### 인증

```bash
export TRACKER_EMAIL="..."          # 계정 이메일
export TRACKER_TOKEN="..."          # API 토큰 (개인 발급)
```

토큰은 **개인 셸 환경변수 또는 로컬 설정 파일**에만 둔다. 저장소 커밋 금지(§5).

### DNS 해석 실패 시 우회

호스트 이름이 해석되지 않을 때 재시도만 반복하지 않는다:

```bash
getent hosts {{TRACKER_HOST}}                                   # 1) 로컬 DNS 확인
curl -sS -H "accept: application/dns-json" \
  "https://1.1.1.1/dns-query?name={{TRACKER_HOST}}&type=A"      # 2) DoH로 IP 조회
curl --resolve {{TRACKER_HOST}}:443:<IP> ...                    # 3) IP 고정해 호출
```

## 3. 위키 (Confluence 기준)

### 원칙
- 위키는 **합의된 결론과 규약**의 자리다. **진행 중 상태는 트래커**, **수치의 정본은 Git**.
- 같은 규약을 위키와 리포에 **동시에** 두지 않는다 — 한 곳을 정본으로, 다른 쪽은 포인터.

### 무엇을 올리나

| 올린다 | 올리지 않는다 |
|---|---|
| 스프린트·주간 요약, 회의록 | 진행 중 작업 상태(→ 트래커) |
| 확정된 규약·역할·프로세스 | 실험 원자료·결과 파일(→ Git) |
| 온보딩·환경 구축 안내 | 미검증 수치 |
| 의사결정 기록(무엇을 왜) | 자격증명 |

### 페이지 작성

```bash
curl -sS -u "$TRACKER_EMAIL:$TRACKER_TOKEN" \
  -X POST "https://{{TRACKER_HOST}}/wiki/api/v2/pages" \
  -H "Content-Type: application/json" -d '{
    "spaceId": "{{WIKI_SPACE_ID}}",
    "status": "current",
    "title": "제목",
    "parentId": "{{WIKI_PARENT_ID}}",
    "body": {"representation": "storage", "value": "<p>본문</p>"}
  }'
```

- 응답의 `id` · `_links.webui`를 확인한다. **HTTP 200이어도 본문이 비면 실패**로 본다.
- 트래커와 같은 자격증명·같은 DNS 우회 절차를 쓴다.

### ⚠️ 수치를 위키에 옮길 때

**위키의 표는 정본이 아니다.** 결과 파일에서 옮긴 수치는 **출처(`파일:줄` 또는 커밋)** 를 함께 적고,
가능하면 **숫자 드리프트 검사**(→ [04](04_automated_review_and_governance.md))의 대상에 포함시킨다.
발표자료·위키의 관측값을 나중에 **합격 기준으로 오인**하는 사고가 실제로 일어난다([APPENDIX 사례 5](APPENDIX_CASE_BIOP02.md)).

## 4. 알림 (Telegram 기준)

### 원칙
- **알림 봇은 모니터링·전달 전용이다. 코드를 쓰지 않는다.** 구현은 사람이 CLI 도구로 한다 → [05](05_human_collaboration.md)
- **채팅은 정본이 아니다.** 알림은 "가서 보라"는 포인터이고, 근거는 링크 건너편에 있다.

### 봇 만들기 · 대상 얻기

1. Telegram에서 **@BotFather** → `/newbot` → **봇 토큰** 발급
2. 알림 받을 곳을 정한다
   - **개인 DM**: 봇에게 아무 메시지나 한 번 보낸다(먼저 말을 걸어야 봇이 보낼 수 있다)
   - **그룹/채널**: 봇을 **관리자로 추가**한다
3. `chat_id` 확인:

```bash
curl -sS "https://api.telegram.org/bot$TELEGRAM_TOKEN/getUpdates" | head -c 800
```

> 개인 chat_id는 양수, 그룹/슈퍼그룹·채널은 **음수**(`-100…`)다. 그룹이 슈퍼그룹으로 승격되면 **id가 바뀐다** — 하드코딩하지 말고 설정값으로 둔다.

### 보내기

```bash
curl -sS -X POST "https://api.telegram.org/bot$TELEGRAM_TOKEN/sendMessage" \
  --data-urlencode "chat_id=$TELEGRAM_CHAT_ID" \
  --data-urlencode "text=[{{TRACKER_KEY}}-123] 검수 blocked — 하드룰 위반
https://{{TRACKER_HOST}}/browse/{{TRACKER_KEY}}-123" \
  -d "disable_web_page_preview=true"
```

### 함정 4가지 (전부 실제로 걸린다)

| 함정 | 대응 |
|---|---|
| **메시지 길이 4096자 제한** | 길면 잘라 보내거나 **요약 + 링크**로. 로그 전문을 붙이지 않는다 |
| **MarkdownV2 이스케이프** | `_ * [ ] ( ) ~ \` > # + - = \| { } . !` 를 모두 `\` 이스케이프해야 한다. 안 하면 **400 에러로 조용히 실패**한다 → 확실하지 않으면 `parse_mode` **없이 평문**으로 보낸다 |
| **레이트 리밋** | 같은 채팅에 초당 다수 전송 시 `429`. 재시도는 응답의 `retry_after` 만큼 대기 |
| **봇이 먼저 말 못 검** | 사용자가 봇에게 먼저 말을 걸거나 봇이 그룹에 있어야 한다 |

### 무엇을 보내고 무엇을 안 보내나

| 보낸다 | 안 보낸다 |
|---|---|
| 티켓 할당·기한 임박·상태 변경 | ❌ 자격증명·토큰 |
| 검수 결과 `blocked` / 사람 판정 필요 | ❌ 미검수 결과 수치 (검수 통과 전 결과 공유 금지) |
| 장기 작업 완료·실패 + 로그 경로 | ❌ 원자료·개인정보 |
| 자원 예약·장애 | ❌ 긴 로그 전문 |

### 채널 분리

`{{CHANNELS}}` 를 목적별로 나눈다 — **공지 / 작업 진행 / 결과 공유(검수 통과 후만) / 자원·장애**.
한 채널에 모으면 **차단 알림이 잡담에 묻힌다.**

### 검수 루프와의 연결

자동 검수 루프의 상태를 채널에 매핑한다 → [04](04_automated_review_and_governance.md)

| 상태 | 채널 | 메시지 |
|---|---|---|
| `blocked` | 장애·긴급 | 하드룰 위반 — 무엇이 걸렸는지 + 경로 |
| `needs_human` | 작업 진행 | 사람 판정 필요 — 담당자 멘션 + 티켓 링크 |
| `provisional` | 작업 진행 | 진행 가능, **공유는 확인 후** |
| 게이트 실패 | 장애·긴급 | **멈춤** — 무엇이 왜 실패했는지 |

## 5. 비밀 관리 (네 시스템 공통)

- 토큰은 **개인 셸 환경변수 또는 사용자 홈의 설정 파일**에만 둔다
- ❌ 저장소 커밋 금지 · ❌ 티켓/위키 본문 금지 · ❌ 채팅 붙여넣기 금지
- `.gitignore`에 설정 파일 패턴을 넣고, **커밋 전 스캔**을 CI에 건다
- 유출 시: **먼저 폐기(revoke)** 하고 그다음에 히스토리를 정리한다 — 순서를 바꾸지 않는다
- 봇 토큰은 **최소 권한**으로. 알림 봇에 저장소 쓰기 권한을 주지 않는다

## 6. 배선 확인 체크리스트

- [ ] §0 정본 표를 채웠고 **중복 저장이 없다**
- [ ] 커밋 작성자 이메일 = 트래커 계정 (스마트 커밋 동작 확인)
- [ ] 티켓 조회가 **`comment` 를 포함**한다 (라이브러리·MCP 호출 포함)
- [ ] 위키에 옮긴 수치에 **출처 표기**가 있다
- [ ] 알림 봇이 **읽기 전용 권한**이고 토큰이 커밋되지 않았다
- [ ] `blocked` / 게이트 실패가 **긴급 채널**로 간다
- [ ] 검수 통과 전 결과가 **결과 공유 채널로 나가지 않는다**
- [ ] 네 시스템이 죽어도 **작업이 멈추지 않는다** (알림은 편의이지 의존이 아니다)

## 7. 실패 모드

| 증상 | 원인 | 대응 |
|---|---|---|
| 스마트 커밋이 무시됨 | 커밋 이메일 ≠ 트래커 계정 | `git config user.email` 교정 |
| "승인 대기"라고 썼는데 이미 승인됨 | 코멘트 없이 조회 | `fields`에 `comment` 추가 |
| 위키 표와 결과 파일 수치 불일치 | 수동 복사 후 원본만 갱신 | 숫자 드리프트 검사 대상에 포함 |
| 알림이 안 옴 | chat_id 변경 / 봇 미초대 | `getUpdates`로 재확인 |
| Telegram 400 에러 | MarkdownV2 미이스케이프 | 평문으로 전송 |
| 호스트 해석 실패 | DNS | DoH 조회 후 `--resolve` |
