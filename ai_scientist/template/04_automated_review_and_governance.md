# 04 — 검수 3층 + 거버넌스 (원칙)

이 하네스의 핵심. 답해야 할 질문은 하나다:

> **"AI가 몇 주간 검수·수정을 도는 동안, 사람이 매번 병목이 되지 않게 하려면?"**

답: **AI가 리뷰 노동을 대신하고, 사람은 판단해야만 하는 항목만 처리한다.**

## 검수 3층

```
① CI 결정론 검증기 (기계)  → blocking. LLM 판단 없음
        ▼
② 자동 리뷰 루프 (AI 적대)  → 게이트 → 큐 → 적대 리뷰 → 리포트
        ▼
③ 사람 게이트              → 티어에 따라 개입 정도가 다름
```

### ① CI 결정론 검증기

**결정론·오프라인 검증만** blocking으로 건다. 최소 3종을 권장한다:

| 검증기 | 무엇을 막나 |
|---|---|
| 검수기 회귀 테스트 | **검수기가 무조건 통과시키는 회귀** — 채점이 케이스에 실제로 제약되는지 |
| 인용 검증기 회귀 테스트 | 조회 실패 시 약한 대체 검색으로 통과시키던 **버그가 죽어 있는지** |
| **숫자 드리프트 검사** | **정본(결과 파일) ↔ 문서 표**의 수치 불일치 |

> **왜 CI인가:** 검증 자산을 만들어 두고도 워크플로가 없으면 **사람이 기억할 때만 돈다.** 눈으로 대조해야만 발견되는 불일치는 며칠~몇 주씩 방치된다.
> **명시적 비범위:** 자동 리뷰 루프의 활성화 플래그는 CI가 건드리지 않는다. 라우터 문서도 손대지 않는다.

### ② 자동 리뷰 루프

```
(주기 스캔 또는 사람 트리거)
   → 결정론 게이트          하드룰 위반? → blocked (즉시 정지)
   → 티어 분류 + 큐 적재
   → 큐 drain               항목마다 호출 스펙 발행 · owner→reviewer 자동 배정
   → AI 적대 리뷰           체크리스트 + 다중 패스 + 헤드라인 수치 재계산
   → 검수 리포트
   → 티어별 처리
```

**설계 규칙 3개:**
1. **결정 항목은 전부 config로 뺀다.** 코드는 도메인 무관하게 유지 → 다른 프로젝트는 스크립트 복사 + 자기 config만 넣으면 작동한다.
2. **기본값 `enabled=false`(dry-run).** 무엇을 할지만 출력하고 실제 행동은 하지 않는다. 팀이 결정 항목을 채우면 **코드 변경 없이** 켠다.
3. **외부 리뷰는 여기서 부르지 않는다.** 이 자리는 내부 적대검수의 자리이고, 외부 리뷰는 **게이트 ① 통과 후**다.

### ③ 사람 게이트 — 티어

| 티어 | 무엇 | 처리 | 사람 개입 |
|---|---|---|---|
| **하드룰 위반** | `{{FORBIDDEN_PHRASES}}` · 필수 필드 누락 · `claim_level` 위반 | `blocked` 즉시 | 정지 — 고쳐야 통과 |
| **Tier C** | `{{TIER_C_PATHS}}` (헤드라인·공개물) | `needs_human` | **사람이 판정** |
| **Tier B** (기본) | 그 외 결과물 | `provisional` | **진행·커밋 허용**, **공유만** 1-클릭 확인 |
| **Tier A** | `{{TIER_A_PATHS}}` (문서·설정) | 가벼운 경로 | 대부분 자동 |

> **설계 의도: "진행을 사람 리뷰에 볼모 잡지 않는다."** 사람이 하드 블로킹하는 건 **헤드라인·공개**뿐이다.

### 하드룰이 "안전 마커"까지 봐야 하는 이유

금지 표현 검사는 **그 표현을 설명하는 문서**(안티패턴 목록·체크리스트 등)에서 오탐을 낸다.
`{{FORBIDDEN_SAFE_MARKERS}}`(금지·아님·not·❌ 등)와 `{{META_FILES}}`로 **"금지어를 설명 중인 맥락"을 면제**한다.
게이트가 자기 규칙 문서에 걸려 넘어지지 않게 하는 장치다.

## 판정 어휘 — ⚠️ 처음부터 정할 것

두 축을 **분리해서** 정의한다:

| 축 | 뜻 | 예 |
|---|---|---|
| **판정** | 결과가 어떤가 | 통과 / 주의 / 기각 / 해당없음 |
| **티어 처리** | 누가 확인하나 | blocked / provisional / needs_human |

⚠️ **반드시 넣어야 할 값 하나:** *"현재 데이터로는 식별 불가 — 추가 작업으로 통과가 되지 않음"*.

이 칸이 없으면 그런 항목이 **"주의"로 뭉뚱그려지고**, "주의"는 *"더 하면 통과될 수도 있다"* 로 읽힌다. 그러면 두 가지 중 하나가 일어난다:

- 달성 불가능한 기준을 붙들고 프로젝트가 멈추거나,
- **데이터를 본 뒤 기준을 낮추게 된다** — 사후 골대 이동, 금지 사항이다.

> 어휘가 부족하면 **프로세스로 메우게 된다.** 실제 사례는 [APPENDIX](APPENDIX_CASE_BIOP02.md)를 볼 것.
> ⚠️ **어휘는 나중에 바꾸기 어렵다** — 기존 리포트의 유효성과 게이트 하드룰에 영향을 준다. **초기에 정한다.**

## 리뷰어 부재 폴백 (소규모 팀)

리뷰어가 1명뿐이라 owner=reviewer가 되는 경우:

- AI 적대 **독립 패스 ≥3** + 리더 확인, 라벨로 그 사실을 기록
- 단 **헤드라인은 타인 1인 확인 필수**
- ⚠️ **독립 패스는 모델 계열을 달리한다** (`{{MODEL_DIVERSITY}}`)

> **왜 모델 다양성인가:** LLM은 **자기 출력을 선호**한다(self-preference). 이 편향은 **같은 모델을 N번 돌려도 상쇄되지 않는다.** 반복 횟수는 분산을 줄일 뿐 독립성을 만들지 못한다.
> 전면 다중모델이 부담되면 **헤드라인·Tier C에 한해** 서로 다른 계열 2개 이상을 요구한다.

## ⚠️ 처음부터 정할 것 — 비판 자체를 검증하는 층

루프가 비판을 **생산**한 뒤 곧바로 **누가 확인할지**로 넘어가면, 비판이 원본을 오독했는지·없는 주장을 공격했는지·근거를 지어냈는지를 판정하는 단계가 없다. 즉 **검수자의 산출물만은 검수를 거치지 않는다.**

값싼 이식안: 검수 리포트의 항목마다 등급을 붙이고 낮은 등급은 내보내지 않는다.

```
유효·치명 / 유효·수정가능 / 부분유효 / 약함 / 부정확 / 근거없음·환각
```

마지막 등급이 특히 중요하다 — **없는 근거를 지어낸 지적**은 잡지 않으면 그대로 결정이 된다.

## 거버넌스 — 자동화가 넘지 못하는 선

`{{PROJECT_NOT}}`에서 파생되는 도메인 금지선 + 아래 공통 금지선을 함께 명시한다.

| 공통 금지 | 이유 |
|---|---|
| ❌ 자격증명·키를 저장소에 커밋 | — |
| ❌ **검수자가 자기 임계값·통제를 스스로 결정** | anti-self-reference. 검수 기준은 **다른 사람이 승인**한다 |
| ❌ 발표자료·메모의 숫자를 합격 기준으로 사용 | 기준의 근거는 **봉인 문서 + 실물 코드**뿐, `파일:줄`로 인용 |
| ❌ 도구의 "못 찾겠다"를 통과로 처리 | 조회 실패는 **에스컬레이션** |
| ❌ **티켓·파일을 열지 않고 상태를 단정** | "없다/미완료/대기 중"은 **실물을 연 뒤에만**. 기억·요약은 근거가 아니다 |

> 뒤 네 항목은 형태가 달라도 뿌리가 같다 — **근거 없이 상태를 주장하는 것.**
> 그래서 규칙도 같은 모양이다: *근거는 실물뿐이고, 인용할 땐 출처를 밝힌다.*

## 완료의 정의 (공유·커밋 전 체크리스트)

"done"은 코드를 다 짰을 때가 아니라 **end-to-end로 검증했을 때**만이다.

- [ ] 아티팩트 완비 (`{{REQUIRED_ARTIFACTS}}` + `{{METRIC_FIELDS}}` + 커밋 해시)
- [ ] 검수 통과 (owner ≠ reviewer). **통과 전 결과 공유 금지**
- [ ] **검증 게이트** — 헤드라인 숫자를 **다시 계산**해 대조. 캐시·이전 세션 출력을 그대로 믿지 않는다
- [ ] 주장 규율 — `claim_level` + 검수 상태 필드, 금지 프레이밍 없음
- [ ] 등록 — 완료 결과를 레지스트리에 등재
- [ ] **숫자·저자·경로를 지어내지 않았다**
- [ ] 상태 기록 + **정직 보고** — 검증한 것/미검증인 것 명시, 실패는 출력과 함께 그대로 보고
