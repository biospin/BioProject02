◆ 개요 — 4개 기둥과 전체 흐름

자동화의 목표는 사람을 빼는 것이 아니라, 사람이 판단해야 할 지점만 남기고 나머지 노동을 에이전트가 대신하는 것. 이 방향은 선행연구를 읽고 의도적으로 내린 포지셔닝이다.

기둥 1

2-레이어 아키텍처

도메인 분석 파이프라인 위에 재사용 논문 생산 하네스를 얹는다. 도메인 지식은 슬롯 하나에 격리.

기둥 2

다중 에이전트 명부

문헌·기획 / 분석 / 집필·그림 / 심사·QA / 발표를 벤치별로 분리. 내부 검수와 외부 리뷰는 격리.

기둥 3

라우팅 + 산출물 계약

자연어를 에이전트로 배정하고, 단계 간에 넘길 것을 계약·스키마로 고정. 없는 것은 <FILL>로 표시.

기둥 4

검수 3층 + 거버넌스

CI 결정론 검증기 → AI 적대 리뷰 → 사람 게이트. 사람은 판단항목만 처리한다.

⚠️ 미해결 갭 5건 — 설계서가 기록하는 미완성 지점

v02에서 가장 새로운 부분. 아래 3~5번은 외부 하네스 문서 2건(적대적 다중 LLM 카운슬 · hyperresearch 덱)과 대조하며 드러난 것으로, 관찰된 갭이지 채택된 설계 변경이 아니다. 공통 모양은 하나다 — 규율은 있는데 강제 수단이 없다.

GAP 1

검증 게이트 ①의 실행 명령이 아직 없다

BIOP01의 p3_concordance.py에 해당하는 BIOP02용 결정론 재계산 스크립트가 리포에 존재하지 않는다. auto_review_gate.py는 DRP 스코프·claim level·metrics 표기를 보는 문서 규칙 검사이지 수치 재계산이 아니다. 채워지기 전까지 게이트 ①은 사람이 수동 대조한다 — 하네스의 가장 큰 미완성 지점.

근거: SKILL.md 실행 흐름 7단계 경고 (실측 2026-07-27)
GAP 2

config가 SKILL.md를 따라오지 않았다

SKILL.md는 5단계 자동 리뷰를 paper-critic 단독으로 고쳤는데, auto_review_config.json의 ai_review.agents는 여전히 ["paper-critic", "reviewer"]다. 켜면 폐기된 에이전트를 부른다. 지금은 enabled=false(dry-run)라 실害는 없으나 활성화 전 정리 필요.

근거: auto_review_config.json 실측 2026-08-03
GAP 3

게이트 ① 이후의 "수정"에 권한 제약이 없다

manuscript-writer가 Write를 보유해, 리뷰 반영 중 원고를 통째로 다시 쓸 수 있고 그때 게이트 ①이 확인한 숫자·인용이 조용히 바뀌어도 에러가 나지 않는다. 방어는 게이트 ②의 사후 재대조뿐이고, check_number_drift.py도 드리프트를 발견할 뿐 발생을 막지 않는다. 같은 규율이 paper-critic에는 도구 수준으로 걸려 있어(쓰기 권한 자체가 없음), 하네스 안에 "권한으로 막은 곳"과 "말로만 막은 곳"이 섞여 있다.

근거: .claude/agents/*.md 프론트매터 실측 · 외부 참조 = hyperresearch "부탁하지 말고 도구를 빼앗아라"
GAP 4

판정 어휘에 "더 해도 pass가 안 됨"을 적을 칸이 없다

critic_status = pass · caution · reject에 "현재 데이터로는 식별 불가"가 없어 그런 항목이 caution으로 뭉뚱그려지고, caution은 "더 하면 pass가 될 수도 있다"로 읽힌다. 실제로 BIOP02-75가 이 빈칸 때문에 티켓 성공 기준 자체를 재정의해 우회했다 — 어휘의 부족을 프로세스로 메운 셈.

근거: schemas/critic_report.schema.json 실측 · BIOP02-75 (Leader 승인 2026-07-24)
GAP 5

비판 자체를 검증하는 층이 없다

루프가 비판을 생산한 뒤(③) 곧바로 누가 확인할지로 넘어간다(④). 비판이 원본을 오독했는지, 없는 주장을 공격했는지, 근거를 지어냈는지를 판정하는 단계가 없다 — Critic의 산출물만은 Critic을 거치지 않는다. 2026-07-27 하루에 Critic 코멘트 4건이 작성자 본인에게 사후 정정된 것이 그 비용이다.

근거: BIOP02-75 #11515·#11521·#11531, BIOP02-59 #11528

설계상 중요한 세 가지 구분

구분 1

계획 에이전트 ≠ 실행 입구

paper-orchestrator(agent)는 계획만 — 서브에이전트는 서브에이전트를 못 낳는다. 실행은 paper-production-orchestrator(Skill)를 메인 루프가 돌린다.

구분 2

도메인 특수성 격리

H&E·병리·DepMap 지식은 spatialpatho-analyst 한 슬롯에 가둠. 나머지 벤치는 어느 논문에도 옮겨 붙는다.

구분 3 · 신설

내부 검수 ≠ 외부 리뷰

paper-critic은 5단계(내부·전체 맥락), venue-reviewer는 8단계(게이트 ① 통과 후·원고 패키지만). 리뷰어가 내부 맥락을 알면 실제 심사자가 겪을 정보 부족을 재현하지 못한다.

안전 기본값: dry-run

enabled:false가 기본 → "무엇을 할지"만 출력. 스터디에서 <DECIDE> 값만 채우고 enabled=true, 코드 변경 없이 활성화. CI 워크플로도 이 플래그는 명시적 비범위로 두었다.
